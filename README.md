# simple-acme
Bunch of scripts related to simple-acme and using this to create Let's Encrypt certs for an on-prem Exchange environment.
# Exchange Simple-ACME Certificate Management

This repository contains a suite of PowerShell scripts designed to automate the lifecycle of Let's Encrypt (or other ACME) SSL certificates for Microsoft Exchange Server environments using [win-acme](https://www.simple-acme.com/).

This solution is built to handle High Availability (HA) scenarios, hybrid environments (e.g., Office 365 Send Connectors), and decentralized certificate deployment across multiple Exchange nodes using a centralized network share for artifacts and secrets.

## Overview of Scripts

The solution is broken down into four distinct scripts to handle initialization, post-renewal exports, HA node recovery, and deployment/cleanup.

### 1. `Wacs-Initial.ps1`
**Purpose:** Sets up the initial win-acme renewal task for your domain using Cloudflare DNS-01 validation.
* Exports a PFX file directly to a designated DFS or UNC network share (`\\NETWORKDRIVE\Share\Certs`).
* Hooks into the post-installation script (`Wacs-Export.ps1`) to handle advanced artifact creation (PEM, CER, Archives).
* Utilizes the `vault://json/` syntax for secrets management, avoiding hardcoded passwords in the command line or registry.

### 2. `Wacs-Export.ps1`
**Purpose:** Advanced artifact generation and secure password resolution. Runs as a post-installation hook from win-acme.
* Reads the renewed PFX generated by win-acme.
* Uses an external `export-secrets.json` file to securely resolve the PFX password based on the BaseName, Subject Alternative Name (SAN), or a default fallback.
* Generates historical archives (`\Archive (dated)`) and the latest files (`\Certs (latest)`).
* Creates `.cer`, leaf `.pem`, and full-chain `.pem` files alongside the `.pfx`.

### 3. `Wacs-Import.ps1`
**Purpose:** Discovers the latest certificate on the network share and deploys it idempotently across the Exchange infrastructure. Designed to be run as a Scheduled Task.
* **Idempotent Updates:** Checks if Send Connectors and Receive Connectors already have the correct `TlsCertificateName`. If they match, it skips the update.
* **Remote Deployment:** Identifies all `SourceTransportServers` for a given Send Connector and uses Exchange cmdlets (`-Server` parameter) to push the certificate and enable SMTP services on those remote nodes without relying on WinRM.
* **Hybrid Aware:** Automatically updates the Exchange Hybrid Configuration TLS certificate name.
* **Cleanup:** Safely removes older Exchange certificates with matching subjects/domains to prevent bloat.

### 4. `Wacs-HA-Renewal.ps1`
**Purpose:** A rapid recovery mechanism for a failed active node in a High Availability setup.
* Because the win-acme secrets vault uses DPAPI (which is machine-specific encryption), a new HA node cannot decrypt the `vault://` credentials created by the failed node.
* This script bypasses the standard vault, manually passing the required tokens and forcing an immediate, unscheduled renewal to get the new node up and running fast.

## Prerequisites

1.  **Simple-ACME:** Installed on the server handling the renewals (default path: `C:\Program Files\simple-acme\wacs.exe`).
2.  **Validation Plugin:** The Cloudflare validation plugin for win-acme (or modify the `Wacs-Initial.ps1` script to use your DNS provider).
3.  **Permissions:** * The renewal processes require Administrator or SYSTEM privileges.
    * The `Wacs-Import.ps1` script should be run by a service account that is a Local Administrator on all Exchange servers and possesses the necessary Exchange RBAC roles to manage certificates and connectors.
4.  **Network Share:** A centralized UNC path (e.g., `\\NETWORKDRIVE\Share`) accessible by the ACME host and the Exchange servers.

## Secrets Management

This suite relies on external JSON files for password management to avoid hardcoding secrets into scripts or scheduled tasks. You need to run simple-acme manually and use 'more options' in order to create these secrets, as they are DPAPI encrypted to a particular host.

Create a file named `export-secrets.json` in your network share root:

```json
[
  { "Key": "default",      "Secret": "YourStrongDefaultPass#2026" },
  { "Key": "example.com",  "Secret": "AnotherPass1!" },
  { "Key": "*.example.com","Secret": "WildcardPass1!" }
]
